ANIMATION SYSTEM — IMPLEMENT FULLY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Use framer-motion for ALL of the following. Every animation must be fast, purposeful, and non-intrusive. Total durations should feel snappy (120ms–350ms). Never make the UI feel slow.

1. Page and view transitions
- Wrap each main view in .
- Enter: opacity 0→1, y +8→0, duration 200ms, ease "easeOut".
- Exit: opacity 1→0, y 0→-4, duration 150ms, ease "easeIn".

2. Modal entrance and exit
- Backdrop: opacity 0→1 (200ms).
- Modal panel: opacity 0→1, scale 0.96→1, y +12→0 (250ms, ease [0.16, 1, 0.3, 1]).
- Exit: reverse, duration 180ms.
- Use AnimatePresence to unmount cleanly.

3. Drawer / side panel entrance
- Slide in from right or left: x ±320→0 (280ms, spring stiffness 300 damping 30).
- Backdrop fade simultaneously.

4. Table and list row stagger
- On initial data load or filter change, rows animate in with staggerChildren 0.03s.
- Each row: opacity 0→1, y +6→0 (150ms).
- Use variants with staggerChildren on the container.

5. Search result reveal
- Results container: AnimatePresence.
- Result cards: stagger 0.04s, opacity 0→1, y +8→0.
- Empty state: fade + slight scale 0.97→1.

6. Expanding/collapsing sections (certificate fields, advanced filters, audit details)
- Use framer-motion layout animations:  on containers.
- Expanding content: AnimatePresence with initial={false}, height animation via animate={{ height: "auto" }} using a motion.div with overflow hidden.
- Duration 250ms, ease [0.04, 0.62, 0.23, 0.98].

7. Button micro-interactions
- All primary and danger buttons: whileTap={{ scale: 0.97 }}.
- Icon-only buttons: whileHover={{ scale: 1.08 }}, whileTap={{ scale: 0.93 }}.
- Loading state: replace button content with a spinning  (lucide) wrapped in motion.div with rotate animation (360deg, repeat Infinity, duration 0.8s linear).

8. Badge and chip animations
- New status chips entering: scale 0→1, opacity 0→1 (180ms spring).
- Removing a filter chip: scale 1→0, opacity 1→0 (150ms).

9. Form field interactions
- Input focus: border-color transitions (CSS transition 150ms) and a soft shadow ring appears.
- Inline validation messages: AnimatePresence, enter with height 0→auto + opacity 0→1 (200ms).
- Error shake: on submit with errors, use keyframes x: [0, -6, 6, -4, 4, 0] (400ms).

10. Skeleton loading states
- Before data loads, show animated skeleton placeholders (pulsing opacity 0.4→0.8 via framer-motion animate with repeat Infinity, repeatType "reverse", duration 1s).
- Match the exact shape of the expected content: table rows, cards, worker result card.

11. Worker card appearance in search
- The result card should animate in with: opacity 0→1, y +16→0, scale 0.98→1 (300ms, ease [0.16, 1, 0.3, 1]).
- Internal sections (documents, certifications) stagger in 80ms after the card.

12. Notification / toast system
- Implement a toast notification system using framer-motion AnimatePresence.
- Toasts enter from the bottom-right: y +40→0, opacity 0→1 (240ms spring).
- Auto-dismiss after 4s with exit animation.
- Variants: success (emerald), error (rose), warning (amber), info (sky).
- Use for: save confirmed, import success, export complete, validation errors, auth events.

13. Hover states on interactive rows and cards
- Table rows: background transitions to #F9FAFB on hover (CSS transition 100ms).
- Cards: box-shadow transitions to shadow-md on hover (CSS transition 150ms).
- Clickable rows: add cursor pointer and a subtle left border accent on hover.

14. Number / counter transitions
- When counts change (worker count in header, result count in search), use a number spring animation or simple crossfade.

15. Empty state entrance
- Empty state illustrations/icons: scale 0.8→1, opacity 0→1 (300ms spring) when they appear.

UX BEST PRACTICES — IMPLEMENT THROUGHOUT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Loading and feedback:
- Every async operation (data load, import, export, save) must show a loading state — skeleton, spinner, or progress bar as appropriate.
- Never show a blank screen while loading. Always show a skeleton.
- After save/import/export: always trigger a toast notification confirming success or showing the error.
- Optimistic UI where practical (e.g. immediately show a worker added to a list while the DB write completes).

Inline validation:
- Required field validation triggers on blur, not only on submit.
- Error messages are specific and in French.
- Successful field validation shows a subtle checkmark icon on blur.
- On form submit with errors: scroll to the first error field, shake the form, show all errors.

Empty states:
- Every list, table, and result area must have a designed empty state.
- Empty states include: an icon (lucide, 48px, muted), a title, a subtitle, and optionally a primary CTA.
- Never show a blank white area.

Accessibility:
- All interactive elements have visible focus rings (the 2px cobalt ring defined above).
- All icon-only buttons have aria-label.
- Modals trap focus and return focus on close.
- Color is never the only indicator of status — always combine color with text or icon.
- All form inputs have associated labels.
- Keyboard shortcuts for common actions (Escape to close modal, Enter to submit) should work correctly.

Tooltips:
- Icon-only buttons and truncated text show tooltips on hover.
- Tooltips use a consistent style: dark background (#1F2937), white text, 12px, 6px radius, 200ms delay before appearing.

Confirmation dialogs:
- Destructive actions (delete, reset, remove admin rights) always require a confirmation modal.
- Use the ModalShell (sm) with danger styling.
- Primary action button is the danger variant.
- Cancel is the secondary variant.
- Confirmation text clearly states what will be deleted/lost.

Keyboard navigation:
- Tab order is logical throughout all forms and modals.
- Arrow keys work in segmented controls and tabs.
- The search input is auto-focused when the search view is activated.
- The first input in a modal is auto-focused on open.

Performance feel:
- Debounce search inputs (300ms) to avoid unnecessary DB queries.
- Use React.memo and useMemo where re-renders are expensive (large tables, filter operations).
- Virtualize long lists if >200 rows using react-window or similar if already in dependencies.
- Avoid layout shifts — reserve space for dynamic content.
